# Codex Float 产品需求文档（PRD）

**版本**：v0.1（MVP）  
**日期**：2026-08-23  
**状态**：待开发  
**产品形态**：Windows 桌面独立悬浮窗，Local-first 开源项目

## 1. 产品概述

### 1.1 一句话定义

Codex Float 是一个常驻于 Windows 桌面的轻量悬浮状态面板，用低打扰的方式展示 Codex 的剩余额度、重置倒计时，以及用户在本机可统计范围内的 Token 使用总量。

### 1.2 产品愿景

让使用 Codex 的个人开发者在不中断工作流的前提下，随时回答三个问题：

1. 我现在还剩多少 Codex 额度？
2. 当前额度什么时候恢复？
3. 我今天在本机一共使用了多少 Token？

### 1.3 产品原则

- **低打扰优先**：默认状态只占用极小桌面空间；用户主动悬停或点击后再显示细节。
- **本地优先**：额度、会话和 Token 聚合数据默认仅保留在本机；不建设云端服务，不上传遥测数据。
- **真实状态优先**：明确标记“实时”“可能已过期”“暂不可用”；绝不将缓存伪装为实时数据。
- **总量优先**：Token 使用仅展示总量，不按模型、不按输入/输出、不按价格拆分。
- **原创实现**：可研究现有开源项目的兼容性、刷新与容错思路，但 UI、交互、架构、实现和品牌均独立设计，不套壳、不复制完整产品结构。
- **可解释性**：每一个状态、数值和错误都有用户可理解的来源说明。
- **安全边界清晰**：不在前端暴露 OAuth Token、Cookie、邮箱、聊天内容或原始会话数据。

## 2. 背景与问题

Codex 订阅额度通常存在短周期和长周期限制。开发者需要打开 Codex 客户端或切换界面才能查看剩余量与重置时间，工作时容易忽略额度状态，也无法快速回顾当天的使用强度。

现有社区工具大致分为三类：侧边栏注入、桌面宠物/浮层、托盘监控。这些方案验证了本地读取额度的可行性，但也存在 UI 依赖官方应用、CDP 调试端口风险、信息密度过高、品牌和交互不统一等问题。

Codex Float 的差异不是“再做一个额度显示器”，而是提供一个独立、安静、可持续使用的个人 AI 工作状态组件。

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户类型 | 典型特征 | 核心诉求 |
|---|---|---|
| 个人开发者 | 每天使用 Codex CLI 或 Codex Desktop 开发 | 不切换窗口即可查看余量与重置时间 |
| AI 工作流重度用户 | 长时间运行多个代码任务 | 及时判断是否适合继续发起高消耗任务 |
| 本地优先用户 | 在意账号数据、隐私和工具稳定性 | 不希望把授权信息和工作数据交给第三方服务 |

### 3.2 核心场景

1. 用户正在 IDE、终端或浏览器中工作，桌面角落的折叠胶囊展示当前 5 小时额度和重置倒计时。
2. 用户准备发起一个长任务，悬停浮窗后查看短周期额度、长周期额度和数据新鲜度。
3. 用户在一天结束时展开面板，确认“今日本机已用 Token 总量”和会话数量，了解工作投入程度。
4. 本地额度读取临时失败时，面板保留最近一次有效快照并明确标为“可能已过期”；达到不可用阈值后不再展示旧值。
5. 用户将面板拖到常用位置、启用开机启动，并在需要专注时打开鼠标穿透模式。

## 4. 目标与非目标

### 4.1 MVP 目标

- 在 Windows 上提供始终置顶、可拖动、可折叠的独立悬浮窗。
- 显示 Codex 当前可用额度窗口的剩余百分比、实际窗口时长和下次重置倒计时；不假设账户必然同时存在 5 小时与周窗口。
- 显示“今日本机已用 Token 总量”，并明确统计边界。
- 支持数据刷新、缓存、重试和新鲜度状态。
- 提供基础设置：位置、开机启动、自动折叠、鼠标穿透、刷新间隔。
- 以开源方式发布，提供可复现构建、隐私说明和故障诊断说明。

### 4.2 非目标

以下内容不属于 MVP，除非后续单独立项：

- 多账号切换、账号池轮换或多账号额度平均。
- 模型维度、输入/输出维度、价格、成本、预算与账单统计。
- 云端账号、同步服务、远程遥测、广告或订阅付费功能。
- 替代 Codex Desktop、Codex CLI 或 ChatGPT 官方客户端。
- 修改、绕过、扩展或规避 OpenAI 任何额度规则。
- 将未公开接口承诺为长期稳定 API。
- 在 Codex Desktop 内注入 UI；该模式即使后续评估，也只能作为明确标记的实验性功能，不纳入 MVP。

## 5. 信息架构与界面设计

### 5.1 窗口状态

| 状态 | 建议尺寸 | 触发方式 | 内容 |
|---|---:|---|---|
| 折叠态 | 约 250 × 64 px | 默认、自动收起、点击收起 | 品牌点、最关键的可用额度窗口、重置倒计时、状态色 |
| 展开态 | 约 320 × 280 px | 点击或悬停 | 全部额度、今日 Token、会话数、更新时间、操作入口 |
| 设置态 | 独立设置窗口或展开态二级页 | 点击设置 | 位置、交互、启动、刷新、数据、诊断 |
| 不可用态 | 与折叠态同宽 | 无有效数据或依赖不可用 | 简短原因、上次有效时间、重试入口 |

### 5.2 折叠态设计

示例：

```text
● Codex      5h 72% · 4小时18分后重置
```

要求：

- 显示通用额度中最关键的短周期窗口；如果无法识别为 5 小时窗口，则显示实际窗口标签。
- 额度颜色：`>50%` 为绿色，`20%–50%` 为琥珀色，`<20%` 为红色。
- “可能已过期”使用低饱和灰黄色小标记；“暂不可用”不显示伪造百分比。
- 鼠标可拖动整个窗口；提供贴边吸附。
- 无边框、圆角、半透明深色玻璃质感；不遮挡主工作区域。

### 5.3 展开态设计

建议布局：

```text
Codex Float                                      ● 实时
────────────────────────────────────────────────────
当前额度
5 小时窗口          72%                 4小时18分后重置
本周窗口            86%                 3天12小时后重置

今日本机已用 Token
1,706,420
今日会话 8 · 上次刷新 刚刚

[刷新]  [固定位置]  [设置]
```

要求：

- 额度按窗口排序：短周期在前、长周期在后。
- Token 只展示一个总量，单位自动格式化为 `K`、`M` 或完整数字；不得默认展示模型、价格或输入/输出拆分。
- 展开态支持“今天 / 7 天 / 30 天”范围；7 天和 30 天显示范围总量与极简每日柱状趋势，本地默认只保留最近 30 天聚合。
- Token 必须显示覆盖状态：`完整覆盖`、`部分覆盖`、`暂不可用` 或 `账号环境不一致`；不得把本地口径与账户口径静默相加。
- “今日本机”必须始终保留，以声明统计范围。
- 最新刷新时间采用相对时间；超过新鲜度阈值需改为明确状态文本。
- 详情区域不得出现授权凭据、账号邮箱、会话内容、原始请求或原始响应。

### 5.4 交互规格

| 交互 | 行为 |
|---|---|
| 单击折叠态 | 展开或收起 |
| 悬停折叠态 | 可选自动展开；由设置控制 |
| 拖动 | 更新窗口坐标并持久化 |
| 双击标题区域 | 切换鼠标穿透 |
| 右键菜单 | 刷新、展开/收起、设置、暂停、退出 |
| 低额度 | 改变状态色；MVP 不弹出侵入式通知 |
| 手动刷新 | 立即请求数据；在进行中禁用重复触发 |

## 6. 功能需求

### 6.1 FR-001：Codex 额度读取

**优先级**：P0

系统应通过本地受控数据源读取当前已登录 Codex 账户的额度窗口信息。

**输入**：本机已登录的 Codex 环境。  
**输出**：标准化额度快照，包括窗口标识、剩余百分比、窗口时长、重置时间、读取时间和数据来源状态。

要求：

- 优先使用 Codex 本地运行时提供的额度信息，不通过第三方云端转发账号数据。
- 数据提供层必须可替换，避免 UI 直接耦合某个非公开协议。
- 无 ChatGPT 登录态、运行时不存在、协议不兼容或字段不完整时，应返回结构化错误而非崩溃。
- 未知窗口保留原始时长标签，不伪造为“5 小时”或“周”。
- 已验证的首选实现通过独立 `codex app-server --stdio` 子进程调用 `account/rateLimits/read`；Windows 不依赖仅支持 Unix 的 app-server daemon 生命周期命令。
- Provider 必须动态处理零个、一个或多个额度窗口；`primary`、`secondary` 只是协议字段，不可硬编码成具体产品标签。

### 6.2 FR-002：刷新、缓存与状态

**优先级**：P0

- 启动时立即刷新一次。
- 正常刷新间隔默认为 60–120 秒之间的随机化轮询，避免固定节奏的无意义请求；具体范围可配置。
- 额度变更通知可触发额外刷新；同一时刻不得并发发起多个读取。
- 读取失败后按 5 秒、15 秒、30 秒重试，随后每 30 秒继续重试，直到成功、用户暂停或应用退出。
- 最近成功数据超过 3 分钟时标记为“可能已过期”。
- 最近成功数据超过 15 分钟时不再展示旧额度，改为“暂不可用”。
- 应在已知重置时间后约 2 秒自动刷新，以尽快反映新窗口。
- 缓存仅保存额度显示所需的标准化字段，默认最长保留 15 分钟。

### 6.3 FR-003：今日 Token 总量

**优先级**：P0（统计边界明确后实现）

系统应展示本机当天可观察到的 Codex Token 总量。

定义：

- 统计指标：`今日已用 Token = 当地自然日内、被本机数据提供层确认的所有 Token 使用量之和`。
- 不按模型、输入/输出、价格、成本或账号池拆分。
- UI 文案固定为“今日本机已用 Token”，避免暗示其覆盖网页、手机、其他电脑或不可观察渠道。
- 数据提供层若仅提供额度百分比而不提供 Token 数，系统必须显示“暂不支持本机 Token 统计”，不得用额度百分比推算 Token。

数据来源优先级：

1. `~/.codex/sessions` 会话 JSONL 中明确提供的 `token_count` 事件；该路径已验证同时覆盖 Codex Desktop 和 Codex CLI/TUI。
2. 本项目自身可观察且可去重的 Codex 使用事件。
3. `account/usage/read` 账户日桶仅用于可选诊断或未来独立的账户口径，不与“今日本机”统计静默合并。
4. 用户明确启用、且不上传凭据的本地统计扩展。

要求：

- 使用本机系统时区划分当天，跨午夜自动归档与归零。
- 同一事件不可被重复累加；必须有稳定的去重键或幂等策略。
- JSONL 聚合应保存文件身份、byte offset 和上一累计值；累计值不变时忽略重复快照，累计值下降时按计数器重置处理，并累计当前 `last_token_usage.total_tokens`。
- Token 数据本地持久化，支持用户在设置中“清空本地统计数据”。
- 任一数据源的覆盖范围必须在设置/诊断页可见。
- 默认保留今天及最近 30 天的每日总量；历史数据到期后自动清理。

### 6.4 FR-004：窗口与个性化

**优先级**：P0

- 支持始终置顶、拖动定位、靠边吸附与位置记忆。
- 支持开机启动，默认关闭，须由用户显式启用。
- 支持开机后自动启动并恢复上次位置和折叠状态。
- 支持鼠标穿透，默认关闭；开启后提供明显的临时关闭方式。
- 默认提供全局恢复快捷键，避免鼠标穿透后无法重新操作窗口。
- 全屏应用时默认自动隐藏；显示器断开、DPI 或分辨率变化导致窗口位于有效工作区外时，自动恢复到主屏幕安全位置。
- 支持自动折叠开关和透明度调节。
- MVP 默认深色主题，后续支持浅色和跟随系统。

### 6.5 FR-005：设置与诊断

**优先级**：P1

设置页至少包含：

- 窗口：置顶、自动折叠、悬停展开、鼠标穿透、透明度、恢复默认位置。
- 数据：刷新区间、缓存开关、清空 Token 统计、当前数据来源和最后成功读取时间。
- 启动：开机启动开关。
- 诊断：Codex 运行时发现状态、版本兼容性、最近错误码、脱敏日志导出说明。
- 关于：版本、开源仓库、许可证、非官方声明、隐私说明。

## 7. 数据模型

### 7.1 标准化额度快照

```json
{
  "schemaVersion": 1,
  "fetchedAtMs": 0,
  "status": "live",
  "source": "local-codex-runtime",
  "windows": [
    {
      "id": "general-short-window",
      "label": "5 小时窗口",
      "remainingPercent": 72,
      "durationSeconds": 18000,
      "resetsAtMs": 0
    }
  ]
}
```

约束：

- `status` 仅可为 `live`、`stale`、`unavailable`。
- `remainingPercent` 只能为 `0–100` 的数值或空；不可用时必须为空。
- UI 不应持久化或显示原始 provider 响应。

### 7.2 本地 Token 日统计

```json
{
  "schemaVersion": 1,
  "localDate": "2026-08-23",
  "timeZone": "Asia/Shanghai",
  "totalTokens": 1706420,
  "sessionCount": 8,
  "coverage": "complete | partial | unavailable | account-mismatch",
  "source": "codex-session-jsonl",
  "updatedAtMs": 0
}
```

约束：

- 仅保存总 Token、会话数、日期、时区、更新时间、来源和覆盖范围。
- 实际存储采用 SQLite，以事务方式同时提交文件游标和每日聚合，避免崩溃后重复累计。
- 不保存 prompt、回复内容、文件路径、项目名称、邮箱、OAuth Token 或 Cookie。

## 8. 技术与架构要求

### 8.1 推荐技术路线

| 层级 | 建议技术 | 职责 |
|---|---|---|
| 桌面容器 | Tauri 2 | Windows 窗口、置顶、透明、拖动、托盘/开机启动能力 |
| 前端 | React + TypeScript | 悬浮 UI、状态展示、设置页、可访问性 |
| 本地核心 | Rust | 配置、窗口控制、IPC、缓存、加密/权限边界 |
| Codex 适配器 | 独立 Provider 模块 | 读取本机 Codex 额度、版本检测、标准化输出 |
| 本地存储 | SQLite 或轻量 JSON + 原子写入 | 设置、短期额度缓存、按日 Token 聚合 |

### 8.2 模块边界

```text
apps/desktop/                 # Tauri + React 桌面应用
crates/core/                  # 领域模型、状态机、缓存与聚合
crates/codex-provider/        # 本地 Codex 额度与 Token 数据提供层
crates/platform-windows/      # 置顶、启动项、窗口吸附等 Windows 能力
packages/ui/                  # 独立设计系统与组件
packages/contracts/           # IPC 与数据结构定义
docs/                         # PRD、架构、隐私、安全、贡献指南
```

### 8.3 Provider 抽象

UI 只能读取统一的领域对象，不得了解 Codex 内部进程、协议或认证细节。

```text
QuotaProvider
  ├─ health() -> ProviderHealth
  ├─ readQuota() -> QuotaSnapshot
  ├─ subscribeChanges() -> optional event stream
  ├─ readTokenUsage(range) -> optional TokenUsageSummary
  └─ readAccountUsage() -> optional AccountUsageDiagnostics
```

这样可以在 Codex 更新后替换 Provider，而不重写窗口和 UI。

## 9. 隐私与安全要求

### 9.1 强制要求

- 不上传任何额度、Token、会话、账号或设备数据。
- 不记录、不显示、不向 renderer 传递 OAuth Token、Cookie、邮箱、聊天内容或原始 app-server 输出。
- IPC 必须只传递白名单化的额度快照和统计对象。
- 日志默认脱敏：路径、用户名、账户标识和疑似 token 必须隐藏。
- 诊断导出前必须展示隐私提示；默认不包含原始日志。
- 本地缓存要有明确有效期，并提供“一键清空全部本地数据”。
- 若必须启用 CDP 或类似调试端口，必须作为实验性功能明确告知风险；MVP 默认不得依赖它。

### 9.2 非官方与兼容性声明

- 产品必须明确声明：非 OpenAI 官方产品，不隶属、未经认可也不受 OpenAI 支持。
- Codex 内部运行时、协议、桌面 DOM 和行为可能随官方版本变化；读取失败应优雅降级。
- 项目不尝试规避、扩展或操控用户的额度限制。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 常驻空闲状态下 CPU 占用应接近零；正常刷新不阻塞 UI；窗口展开反馈应即时。 |
| 稳定性 | Provider 崩溃、Codex 退出、网络/运行时异常不应导致浮窗崩溃。 |
| 可访问性 | 状态色必须搭配文字；键盘可打开设置和退出；支持系统缩放。 |
| 可维护性 | Provider、缓存、UI、Windows 平台能力分层；关键状态机与数据归一化具备单元测试。 |
| 可观测性 | 仅本地脱敏日志；错误码可用于用户反馈和 Issue 排查。 |
| 兼容性 | MVP 目标为 Windows 11 x64；Node/Rust 版本与 Tauri 要求在 README 明确写出。 |

## 11. 验收标准

### 11.1 P0 功能验收

1. 已登录且 Provider 兼容时，启动后 10 秒内展示至少一个有效额度窗口。
2. 折叠态显示额度百分比和重置倒计时；展开态展示所有已识别窗口。
3. 额度刷新成功后状态标记为“实时”；超过 3 分钟未刷新变为“可能已过期”；超过 15 分钟不展示旧额度。
4. 用户可拖动窗口，重启后位置、折叠状态和交互设置保持一致。
5. 用户可手动刷新，并能看到刷新进行状态和失败状态。
6. MVP 必须展示“今日本机已用 Token”总量及覆盖状态；跨午夜后新日期统计从零开始，并能查看最近 7 天与 30 天总量和趋势。
7. 在 Token 数据源不可用时，明确显示不可用原因，不推算或虚构 token 数。
8. 应用不将授权凭据、会话文本或账号信息展示在 UI、缓存、日志或诊断导出中。
9. 用户可以清空 Token 日统计和短期缓存。
10. 应用退出、Codex 退出或 Provider 出错时，桌面窗口保持稳定并给出可理解状态。

### 11.2 UI 验收

1. 折叠态在 100% DPI 下不大于约 250 × 64 px。
2. 展开态在 100% DPI 下不大于约 320 × 280 px。
3. 低额度状态在深色背景下具有清晰可读的文字和图标，不仅依赖颜色。
4. 不可用状态不显示过期百分比作为当前值。
5. 中文为默认文案语言，术语统一、无未翻译的内部错误信息。

## 13. 风险与应对

| 风险 | 影响 | 应对策略 |
|---|---|---|
| Codex 内部协议变化 | 额度读取失效 | Provider 模块化；版本检测；显示不可用而非错误数值；快速发布兼容修复。 |
| 本地 Token 与账户日桶口径不一致 | 用户误认为二者是同一账单口径 | 主界面使用本地 JSONL 聚合；账户日桶仅作独立诊断；禁止静默相加并显示覆盖状态。 |
| 读取机制接触敏感授权环境 | 隐私或安全风险 | 白名单 DTO、最小权限、无遥测、无 token 日志、默认不依赖 CDP。 |
| Windows 窗口行为不一致 | 浮窗影响日常工作 | 提供快速隐藏、位置重置、鼠标穿透切换、开机启动默认关闭。 |
| 用户将额度视作精确账单 | 产生误解 | 使用“实时/过期/不可用”状态；明确额度与 Token 统计的不同边界。 |
| 开源依赖许可证与品牌风险 | 发布受阻 | 仅参考思路；审计依赖许可证；保留必要署名；采用独立品牌与非官方声明。 |

## 14. 开源发布要求

- 项目名称暂定：`Codex Float`。
- 许可证确定为 MIT。
- 任何直接复用的第三方代码必须保留原许可和版权声明；优先重写实现而非复制。
- README 必须包含：功能边界、支持环境、安装方式、隐私说明、故障诊断、卸载方式、非官方声明。
- 仓库必须包含：`SECURITY.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`（可选）、Issue 模板和脱敏 Bug Report 指引。
- 禁止将用户的授权文件、日志、缓存或截图中的敏感信息提交到仓库。

## 16. 成功指标

MVP 不收集远程遥测，因此成功指标以本地测试、Issue 反馈和发布质量评估：

- 在支持的 Codex 环境中，额度读取成功且状态与官方客户端可见额度一致。
- 用户无需打开 Codex 主窗口即可在 1 秒内理解当前额度状态。
- 额度不可用时，不出现伪造、误导或无时间标记的旧数据。
- Token 数据若启用，用户可明确理解其为“本机可观测总量”，而不是全账户官方账单。
- 项目可被独立开发者在干净 Windows 环境中按 README 成功构建和运行。
