# Codex Float 项目状态

**基线日期**：2026-10-09
**代码基线**：当前 `master` 工作树（本轮 patch 已通过自动化验证）
**目标平台**：Windows 11 x64  
**当前阶段**：核心回归修复已通过自动测试与 Debug 构建；Windows 交互实机验收和发布工程仍待完成

## 1. 状态口径

本文只按以下三种证据判断完成度：

- **已完成**：源码已接入正式运行路径，并有自动化测试、构建结果或 Windows 实机证据。
- **部分完成**：代码已经存在，但缺少完整状态机、跨场景验收或发布级证据。
- **未完成**：正式运行路径中尚无对应实现，或没有生成所需交付物。

“代码存在”“编译通过”和“Windows 实机可用”不是同一件事。后续开发必须分别记录。

## 2. 总体结论

Codex Float 已经具备可日常运行的核心垂直切片：能够显示 Codex 额度、本机可观测 Token、历史趋势，并提供基本悬浮窗交互。当前 Debug 版本已经在本机真实运行。

项目还不是可公开发布的稳定版本。主要缺口是：Provider 的发布级容错与诊断、设置页、开机启动、完整多显示器/DPI/睡眠测试、安装升级卸载、代码签名与发布自动化。

## 3. 已完成

### 3.1 产品与隐私边界

- 已定义 Windows 本地优先悬浮窗产品形态。
- 已明确额度与“本机可观测 Token”是两种不同口径，禁止静默合并。
- 已明确不展示价格、模型拆分、输入/输出拆分。
- renderer 只接收白名单 DTO，不接收邮箱、OAuth Token、Cookie、会话正文或原始 app-server 响应。
- 已提供 `PRIVACY.md`、`SECURITY.md`、M0 技术验证和 PRD。

### 3.2 正式桌面工程

- Tauri 2 + React 19 + TypeScript + Vite + Rust 工程已建立。
- SQLite 使用 bundled 模式，无需用户额外安装 SQLite。
- Windows 窗口已配置为透明、无边框、不可缩放、始终置顶、跳过任务栏。
- Debug 可执行文件可生成：

```text
apps/desktop/src-tauri/target/debug/codex-float.exe
```

### 3.3 Codex 额度读取

- 已通过独立 `codex app-server --stdio` 完成初始化和 `account/rateLimits/read`。
- Windows 优先发现原生 `codex.exe`，必要时回退到 `codex.cmd`。
- `.cmd` 通过 `cmd.exe /d /c` 启动，并使用 `CREATE_NO_WINDOW` 隐藏控制台窗口。
- 动态解析零个、一个或多个额度窗口，不把 `primary`/`secondary` 硬编码成固定产品含义。
- 已实际显示 5 小时和滚动 7 天额度、剩余百分比及重置时间。
- 冷启动稳定性已加强：初始化等待 4 秒、额度等待 8 秒、外层总等待 15 秒。
- 已实现 `live`、`stale`、`unavailable` 状态；空窗口和协议错误不会标记为 `live`。
- 已实现 SQLite 持久化额度缓存：3 分钟内为较新、最长保留 15 分钟，并有 single-flight 与 5/15/30 秒失败退避。
- 普通读取遵守缓存和退避；两个窗口的手动刷新会通过专用 command 强制尝试 Provider，仍由 single-flight 合并并发请求，失败时保留可用的 stale 缓存。
- 额度按返回的所有窗口动态解析，并按窗口时长排序；产品目前仍按 120 秒轮询，不会按 reset 时间单独调度刷新。

### 3.4 Token 数据口径与本机统计

- 优先读取 `account/usage/read` 的允许字段；日桶包含今天时，今天、7 天、30 天和趋势整组使用账户数据。
- 账户日桶只有历史数据时，今天明确显示“待结算”；账户读取失败或没有有效日桶时，整组回退到本机统计，绝不混算账户和本机数值。
- 账户 Token 数据仅保存在内存 120 秒并受 single-flight 保护；手动刷新会绕过该缓存。
- 优先使用 `CODEX_HOME\sessions`，否则回退到用户配置目录；只读增量扫描 JSONL。
- 按 byte offset 增量读取并保存游标。
- 使用事件键与 SQLite 主键实现幂等去重。
- 处理重复累计快照和会话累计计数器回退。
- 使用事件时间戳和本机时区归属自然日。
- 展示今天、最近 7 天、最近 30 天和最近 7 天趋势。
- 自动清理超过 30 天的事件和每日聚合。
- 支持一键清空 `events` 与 `daily`，保留扫描游标以避免旧数据在下一次扫描时恢复；不会删除 Codex 原始会话文件。
- SQLite 不保存原始 JSONL 路径或会话正文。

### 3.5 窗口基础交互

- 折叠态和展开态可切换。
- 展开态显示全部额度、Token 总量、趋势、更新时间、刷新和清空入口。
- 两个窗口的刷新按钮均触发强制刷新；刷新进行时禁用重复点击，失败时保留上一份快照并提示失败。
- 标题区域使用 Tauri `startDragging()` 原生拖动。
- `core:window:allow-start-dragging` 仅授权给 `float` 窗口；主窗口不再拥有该权限。
- 用户已用真实鼠标确认拖动可用。
- 拖动按钮区域不会启动窗口拖动。
- 窗口位置与展开状态写入 SQLite。
- 启动时恢复有效坐标；无效坐标回退到当前工作区右下角。
- 展开/折叠改变尺寸后会将窗口约束在当前显示器工作区内。
- 已实现 24 物理像素靠边吸附逻辑。

### 3.6 后台运行能力

- 已实现系统托盘菜单：显示窗口、退出 Codex Float。
- 关闭窗口时隐藏到托盘，不直接退出进程。
- 已实现 `Ctrl+Shift+Space` 全局快捷键切换鼠标穿透；托盘显示浮窗时会主动关闭穿透。
- 已实现全屏前台应用检测；用户主动隐藏状态与全屏自动隐藏状态已分开处理，仍待真实交互验收。

## 4. 部分完成

### 4.1 额度 Provider 状态机

当前已具备持久化缓存、single-flight、退避重试和动态窗口解析，但距离发布级容错仍有差距：

- 尚无按已知 reset 时间调度的刷新；
- 错误状态仍归并为 `unavailable`，缺少发现失败、启动失败、初始化超时、协议错误、认证错误等脱敏诊断码；
- app-server 子进程的进程树退出及异常路径清理尚未完成专门测试；
- `tools/app_server_probe.py` 当前还会调用 `account/usage/read`，该方法在当前 CLI 上可能超时，探针与产品实际额度路径没有完全解耦；
- app-server 是内部协议，尚无版本/能力协商和兼容矩阵。

### 4.2 Windows 位置与显示器恢复

已有位置保存、工作区约束和回退代码，但尚未形成完整证据：

- 多显示器拔插；
- 主副屏切换；
- 混合 DPI；
- 分辨率变化；
- 任务栏位于顶部、左侧或右侧；
- 远程桌面进入/退出；
- 睡眠/唤醒；
- Windows 虚拟桌面。

### 4.3 靠边吸附

代码已接入 `onMoved`，但尚未完成真实鼠标、多显示器和混合 DPI 验收，因此不能标记发布级完成。

### 4.4 鼠标穿透

全局快捷键和原生 API 已接入，但：

- 状态未持久化；
- 没有设置页开关；
- 托盘“显示窗口”会主动关闭穿透模式；
- 尚未验证快捷键冲突、睡眠恢复和异常退出后的状态。

### 4.5 全屏自动隐藏

已有 500ms 轮询实现，但尚缺：

- 无边框全屏、独占全屏、视频全屏、游戏全屏测试矩阵；
- 用户主动隐藏与全屏自动隐藏已在代码状态机中分离，并有单元测试；
- 全屏期间用户关闭窗口后，退出全屏不会自动重新显示；该行为仍需 Windows 实机确认；
- 多显示器上仅一块屏幕全屏时的行为定义。

### 4.6 托盘与后台运行

托盘和关闭到托盘代码已实现并可构建，但尚未完成完整实机验收：

- 图标在不同 Windows 缩放下的显示；
- 左键/右键行为；
- Explorer 重启后的托盘恢复；
- 多次启动时的单实例行为；
- 退出时 app-server 子进程清理。

### 4.7 UI 与交互质量

核心 UI 可用，但还不是商业化完成度：

- 没有设置页和诊断页；
- 手动刷新有加载状态并禁用重复点击；
- 浮窗折叠态显示额度 reset 倒计时，主窗口显示 Token 覆盖范围；
- 没有低额度分级颜色与无障碍文字提示的完整实现；
- 没有会话数量；
- 没有悬停展开、自动折叠、透明度调节和跟随系统主题；
- 错误原因只显示“额度暂不可用”，可解释性不足；
- 前端测试只覆盖格式化，没有组件交互和 IPC 集成测试。

### 4.8 代码架构

PRD 设想 Provider、平台能力和 UI 分层，但当前主要逻辑集中在：

```text
apps/desktop/src-tauri/src/lib.rs
apps/desktop/src/main.tsx
```

这对当前原型可接受，但继续叠加设置、诊断、迁移和发布能力会显著增加回归风险，需要在不改变行为的前提下拆分模块。

## 6. 已知风险与技术债

| 风险 | 当前影响 | 优先处理方向 |
|---|---|---|
| app-server 内部协议变化 | 额度可能突然不可用 | Provider 模块化、能力探测、错误码、持久化缓存 |
| 冷启动/并发刷新 | 可能生成多个子进程或偶发超时 | single-flight、取消与子进程生命周期测试 |
| 内存额度缓存 | 重启后没有 stale 降级 | SQLite 持久化标准化快照 |
| 单文件 Rust 核心 | 修改一项容易回归其他功能 | 按 provider/token/window/store 拆分并保持测试绿灯 |
| 单文件 React UI | 设置与诊断继续加入会失控 | 拆分 hooks、组件和 IPC client |
| 全屏隐藏状态混用 | 用户主动隐藏可能被自动恢复 | 显式状态机区分 user-hidden/fullscreen-hidden |
| 多屏/DPI 证据不足 | 窗口可能丢失或越界 | 建立 Windows 手工/自动化矩阵 |
| 缺少安装与签名 | 无法面向普通用户发布 | NSIS、升级、签名、干净机验收 |
